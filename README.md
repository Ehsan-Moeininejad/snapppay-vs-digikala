# مقایسه قیمت بلک فرایدی اسنپ‌پی با دیجی‌کالا
SnappPay Black Friday vs Digikala price comparison

**لینک گزارش زنده (هر 30 دقیقه به‌روز می‌شود):** https://ehsan-moeininejad.github.io/snapppay-vs-digikala/


کراولری که تمام محصولات بلک فرایدی اسنپ‌پی را می‌خواند، هر محصول را روی دیجی‌کالا پیدا می‌کند و نشان می‌دهد قیمت دیجی‌کالا چند درصد بالاتر یا پایین‌تر است. خروجی یک گزارش HTML تیره و فارسی به‌همراه CSV است.

## 1. منابع داده

| منبع | آدرس | محتوا |
|---|---|---|
| لندینگ محصولات اسنپ‌پی | `snapppay.ir/blackfriday/data/products.json` | حدود 700 محصول از حدود 330 فروشگاه، با قیمت، قیمت قبل، کش‌بک و لینک فروشگاه |
| تقویم تخفیف‌ها | `snapppay.ir/timetable/products.json` | حدود 400 آفر زمان‌دار: آنلاین (اپ اسنپ‌پی)، حضوری، لایو؛ وچرها کنار گذاشته می‌شوند |
| جستجوی دیجی‌کالا | `api.digikala.com/discovery/api/v2/search?q=…` | 20 نتیجه‌ی اول جستجو با قیمت فروش، قیمت قبل و وضعیت شگفت‌انگیز |

هر دو فایل اسنپ‌پی JSON ساده هستند (همان فایلی که صفحه‌ی لندینگ بارگذاری می‌کند)؛ نیازی به مرورگر یا HTML parsing نیست. همه‌ی قیمت‌ها به **تومان** است (API دیجی‌کالا ریال برمی‌گرداند و تقسیم بر 10 می‌شود).

## 2. منطق تطبیق محصول

برای هر محصول اسنپ‌پی:

1. عنوان کوتاه‌سازی می‌شود (توضیحات بعد از «،» و پرانتزها حذف می‌شوند) و در دیجی‌کالا جستجو می‌شود.
2. هر نتیجه با سه معیار امتیاز می‌گیرد:
   - شباهت عنوان؛ اعداد و کلمات لاتین (مدل، ظرفیت، سایز) وزن دو برابر دارند.
   - تطابق کامل مدل: اگر `S24` در عنوان اسنپ‌پی باشد و نتیجه `S25` باشد، تطبیق رد می‌شود.
   - منطقی‌بودن قیمت: قیمت خیلی دور (مثلاً برچسب 800 هزار تومانی برای PS5) رد می‌شود.
3. واژه‌های لوازم جانبی (برچسب، قاب، گلس، کاور …) اگر فقط در عنوان دیجی‌کالا باشند، نتیجه را رد می‌کنند.
4. معادل‌های فارسی/انگلیسی یکسان‌سازی می‌شوند: آیفون = iPhone، پلی‌استیشن = PlayStation، گیگ = گیگابایت، ویتامین ث = C.

| سطح اطمینان | معنی | در آمار |
|---|---|---|
| بالا | مدل و مشخصات عددی یکسان | ✓ |
| متوسط | شباهت قابل قبول، نیازمند بررسی انسانی | ✓ |
| ضعیف / بدون نتیجه | معادل مطمئن پیدا نشد | ✗ |

تست‌های `tests/test_matcher.py` و `tests/test_recheck.py` (44 تست) با داده‌ی واقعی (PS5، آیفون 17، Galaxy S24 FE، ویتامین C، لاستیک KB27 …) نوشته شده‌اند: `python -m pytest -q`

### بازبینی (Recheck)

بعد از تطبیق اولیه، برای هر نتیجه صفحه‌ی محصول دیجی‌کالا (`product/v1/products/{id}`) خوانده می‌شود: برند فارسی و انگلیسی، عنوان کامل فارسی و انگلیسی. سپس `src/recheck.py` دوباره مقایسه می‌کند:

| نتیجه | چه زمانی |
|---|---|
| رد (محصول متفاوت) | نسخه‌ی متفاوت (Pro، Plus، NC، OLED، دوقلو، Sensitive)، طعم یا رایحه‌ی متفاوت، جنسیت یا گروه سنی متفاوت (زنانه و مردانه، بچه‌گربه و بالغ)، حجم یا وزن یا تعداد بسته‌ی متفاوت، کالای دیجی‌کالا همراه با لوازم اضافه |
| نیازمند بررسی | برند دیجی‌کالا در عنوان یا نام فروشنده‌ی اسنپ‌پی نیست، دیجی‌کالا مدل یا حجم مشخص دارد ولی عنوان اسنپ‌پی ندارد، کلمه‌ی کلیدی اسنپ‌پی در دیجی‌کالا نیست، طلا و جواهر بدون کد مدل، عنوان خیلی کلی |
| تأیید | هیچ‌کدام از موارد بالا؛ یا کد مدل مشترک (مثل GHM-839) |

اگر بهترین نتیجه رد شود، تا دو نتیجه‌ی بعدی هم بازبینی می‌شوند. دلیل هر تصمیم در ستون `recheck` (CSV و اکسل) و زیر ستون وضعیت در گزارش آمده است. اطلاعات محصولات دیجی‌کالا در `data/dk_products_cache.json` نگه داشته می‌شود تا هر محصول فقط یک بار خوانده شود. آمار بالای گزارش فقط از تطبیق‌های تأییدشده (اطمینان بالا + بازبینی موفق) محاسبه می‌شود.

بررسی دستی 2026-11-23 روی 266 تطبیق اولیه: 126 تأیید، 128 نیازمند بررسی، 12 رد. نمونه‌های ردشده: لاستیک دو حلقه در برابر تک‌حلقه، غذای بچه‌گربه در برابر بالغ، iPhone 8 در برابر 8 Plus، یخچال تک در برابر دوقلو، دهان‌شویه سفیدکننده در برابر Sensitive، تلویزیون معمولی در برابر OLED، طعم‌های متفاوت، شلوار دخترانه در برابر مردانه، بسته‌ی 3 عددی در برابر تکی.


## 3. خروجی‌ها

| فایل | محتوا |
|---|---|
| `docs/index.html` | گزارش: خلاصه، روند، تفکیک دسته‌بندی، بیشترین شکاف‌ها، جدول کامل با فیلتر |
| `data/report.xlsx` | اکسل با شیت‌های خلاصه، همه‌ی تخفیف‌های اسنپ‌پی، دیجی‌کالا ارزان‌تر، اسنپ‌پی ارزان‌تر و «در دیجی‌کالا پیدا نشد» |
| `data/latest.csv` | همه‌ی ردیف‌ها (UTF-8 BOM، مستقیم در Excel باز می‌شود) |
| `data/latest.json` | همان داده به‌همراه خلاصه |
| `data/summary_history.csv` | یک خط به‌ازای هر اجرا، برای نمودار روند |

وضعیت هر تخفیف در دیجی‌کالا (`dk_status`): «تطبیق قطعی» (مبنای آمار)، «نیازمند بررسی»، «نامشخص» (کالای مشابه هست ولی معادل قطعی نیست) و «در دیجی‌کالا پیدا نشد» (جستجو هیچ کالای نزدیکی برنگرداند). در صفحه‌ی گزارش هم دکمه‌های دانلود اکسل برای همه، دیجی‌کالا ارزان‌تر، پیدا نشده و نمای فیلترشده وجود دارد.

ستون‌های کلیدی CSV: `diff_pct` (مثبت = دیجی‌کالا گران‌تر)، `verdict`، `confidence`، `snapp_effective` (قیمت اسنپ‌پی پس از کش‌بک)، `dk_is_incredible`، `live_status` / `live_text` (زمان پخش آفرهای تقویم).

## 4. محل اجرا — کاملاً روی GitHub، بدون وابستگی به کامپیوتر شخصی

همه‌چیز روی سرورهای GitHub Actions (`ubuntu-latest`) اجرا می‌شود و گزارش روی GitHub Pages منتشر می‌شود؛ هیچ مک یا سرور شخصی‌ای لازم نیست.

- API جستجوی دیجی‌کالا اولین درخواست از خارج ایران را با یک ریدایرکت 307 و کوکی چالش جواب می‌دهد؛ `requests.Session` همان کوکی را نگه می‌دارد و درخواست دوم داده‌ی کامل برمی‌گرداند. در تست 2026-11-23 از سرور Cloudflare لندن پاسخ 200 با داده‌ی کامل گرفته شد.
- API قدیمی `v1/incredible-offers` از خارج ایران `"data":[]` (خالی) برمی‌گرداند؛ دلیل 0 ردیفِ کراولر شگفت‌انگیزها همین است، نه مسدود بودن کامل.
- مرحله‌ی «Can this runner reach SnappPay and Digikala?» در هر اجرا وضعیت دسترسی را در لاگ نشان می‌دهد.

**راه جایگزین (فقط اگر دسترسی مستقیم از GitHub قطع شد): پراکسی رایگان Cloudflare**

1. dash.cloudflare.com → Workers & Pages → Create → Worker → محتوای `cloudflare/worker.js` را جایگزین کد کنید → Deploy.
2. در تنظیمات Worker یک Secret به نام `PROXY_KEY` با یک متن تصادفی طولانی بسازید.
3. در ریپو: Settings → Secrets and variables → Actions → دو Secret: `DK_PROXY_URL` (آدرس Worker) و `DK_PROXY_KEY` (همان متن).
4. از اجرای بعدی، همه‌ی درخواست‌ها از Cloudflare عبور می‌کند. با پاک کردن این دو Secret، دوباره مستقیم اجرا می‌شود.

## 5. زمان‌بندی و لینک گزارش

- `.github/workflows/compare.yml` هر 30 دقیقه (دقیقه‌های 07 و 37) اجرا می‌شود؛ هر اجرای کامل حدود 5 تا 8 دقیقه طول می‌کشد (4 درخواست هم‌زمان، 0.3 ثانیه فاصله).
- زمان‌بند خود GitHub روی ریپوهای جدید گاهی دیر یا اصلاً اجرا نمی‌کند؛ مثل پروژه‌های قبلی، cron-job.org هر 30 دقیقه این API را صدا بزند:
  `POST https://api.github.com/repos/Ehsan-Moeininejad/snapppay-vs-digikala/actions/workflows/compare.yml/dispatches`
  بدنه: `{"ref":"main"}` — هدرها: `Authorization: Bearer <token>` و `Accept: application/vnd.github+json`
- لینک گزارش: Settings → Pages → Source: Deploy from a branch → Branch: `main` و پوشه‌ی `/docs` → Save. لینک: `https://ehsan-moeininejad.github.io/snapppay-vs-digikala/` — هر کامیت گزارش، این صفحه را به‌روز می‌کند. GitHub Pages رایگان فقط برای ریپوی public فعال است، پس این لینک برای هر کسی که آن را داشته باشد باز است.
- اجرای آزمایشی سریع: Actions → SnappPay vs Digikala price compare → Run workflow → `limit = 30`.

## 6. اجرای دستی

```bash
python3 -m pip install -r requirements.txt
python3 src/crawler.py            # کامل
LIMIT=30 python3 src/crawler.py   # آزمایشی
```

کدهای خروج: `0` موفق، `2` فید اسنپ‌پی در دسترس نیست، `3` API دیجی‌کالا از این ماشین در دسترس نیست (راه جایگزین بخش 4)، `4` بیش از نیمی از جستجوها خطا داده (گزارش قبلی دست‌نخورده می‌ماند).

## 7. ملاحظات تفسیر

- «قیمت قبل از تخفیف» اسنپ‌پی در بسیاری از محصولات لندینگ چند برابر قیمت بازار است؛ مقایسه فقط روی قیمت نهایی انجام می‌شود.
- بخش بزرگی از محصولات لندینگ (پوشاک، طلا، محصولات فروشگاه‌های کوچک) معادل دقیق در دیجی‌کالا ندارند؛ نرخ تطبیق در کالای دیجیتال، سلامت، آرایشی و خودرو بالاتر است.
- آفرهای تقویم زمان‌دار و با موجودی بسیار محدود هستند (گاهی 1 عدد در هر نوبت)؛ مقایسه‌ی آن‌ها جنبه‌ی ادراک قیمت دارد نه دسترسی واقعی.
